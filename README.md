# Практическая работа № 1. Конечные автоматы

**Вариант 10**

## 1. Цель работы и постановка задачи

**Цель работы:** реализация и исследование детерминированных и недетерминированных конечных автоматов.

### 1.1. Задание для ДКА

Построить ДКА, допускающий в алфавите `{0, 1}` все цепочки нулей и единиц с одинаковыми парами символов на обоих краях цепочки.

Пара на левом краю — первые два символа, пара на правом краю — последние два:

`L₁ = {w ∈ {0, 1}* | |w| ≥ 2, w₁w₂ = wₙ₋₁wₙ}`, где `n = |w|`.

У цепочек длиной 0 и 1 нет пары символов на краю, поэтому они в язык не входят. При `n = 2` обе пары совпадают с самой цепочкой, поэтому любая цепочка длины 2 допускается. При `n = 3` пары перекрываются (`w₁w₂` и `w₂w₃`) и совпадают только у `000` и `111`.

### 1.2. Задание для НКА

Построить НКА, допускающий язык из цепочек из 0 и 1, в которых хотя бы на одной из последних пяти позиций стоит 1:

`L₂ = {w ∈ {0, 1}* | ∃ i: max(1, n − 4) ≤ i ≤ n, wᵢ = 1}`, где `n = |w|`.

Если цепочка короче пяти символов, последними пятью позициями считается вся цепочка. Пустая цепочка не содержит единиц и не допускается.

### 1.3. Требования к реализации

Подготовить модели автоматов в формате JFLAP и программную реализацию на Java. Переходы должны выполняться по таблицам, без использования функций обработки строк. Результаты распознавания на одинаковых тестовых цепочках должны совпадать с результатами соответствующего автомата в JFLAP.

## 2. Состояния и таблицы переходов ДКА и НКА

В таблицах начальное состояние отмечено `→`, допускающее — `*`.

### 2.1. Детерминированный конечный автомат

Множество состояний: `Q = {q0, …, q14}`. Алфавит: `Σ = {0, 1}`. Начальное состояние — `q0`, множество допускающих состояний — `F = {q3, q6, q9, q12}`.

Автомат запоминает первую пару символов (она больше не меняется) и следит за окончанием прочитанной части. Для каждой из четырёх возможных первых пар нужно различать только три случая окончания, поэтому после двух символов автомат попадает в одну из четырёх групп по три состояния.

| Состояние | 0 | 1 | Первая пара | Окончание прочитанной части |
|-----------|---|---|-------------|-----------------------------|
| → q0 | q1 | q2 | — | ничего не прочитано |
| q1 | q3 | q6 | — | прочитан один символ `0` |
| q2 | q9 | q12 | — | прочитан один символ `1` |
| * q3 | q3 | q5 | 00 | `00` |
| q4 | q3 | q5 | 00 | `10` |
| q5 | q4 | q5 | 00 | `1` |
| * q6 | q7 | q8 | 01 | `01` |
| q7 | q7 | q6 | 01 | `0` |
| q8 | q7 | q8 | 01 | `11` |
| * q9 | q11 | q10 | 10 | `10` |
| q10 | q9 | q10 | 10 | `1` |
| q11 | q11 | q10 | 10 | `00` |
| * q12 | q14 | q12 | 11 | `11` |
| q13 | q14 | q12 | 11 | `01` |
| q14 | q14 | q13 | 11 | `0` |

![ДКА, вариант 10](images/DFA.png)

**Обоснование корректности.** Первые два символа переводят автомат из `q0` через `q1` или `q2` в допускающее состояние той группы, которая соответствует первой паре. Это верно, потому что при `n = 2` цепочка всегда принадлежит языку. Дальше автомат остаётся в своей группе, то есть первая пара запоминается навсегда. Внутри группы состояние соответствует окончанию прочитанной части, записанному в таблице. Это проверяется по каждому переходу: например, в группе `00` из любого состояния по `1` окончание становится «`1`» (`q5`), из `q5` по `0` — «`10`» (`q4`), а из `q3` или `q4` по `0` — «`00`» (`q3`). Допускающее состояние каждой группы — единственное, в котором окончание совпадает с первой парой. Следовательно, автомат принимает цепочку ровно тогда, когда `w₁w₂ = wₙ₋₁wₙ`.

**Минимальность.** Состояния из разных групп различимы: они по-разному реагируют на продолжения. Внутри группы различимы допускающее состояние, состояние, из которого допускающее достигается одним символом, и состояние, из которого для этого нужно два символа. Алгоритм минимизации (Мура) не объединяет ни одной пары из 15 состояний, поэтому автомат минимален.

Модель: [Variant10_DFA.jff](Variant10_DFA.jff).

### 2.2. Недетерминированный конечный автомат

Множество состояний: `Q = {q0, q1, q2, q3, q4, q5}`. Алфавит: `Σ = {0, 1}`. Начальное состояние — `q0`, множество допускающих состояний — `F = {q1, q2, q3, q4, q5}`.

| Состояние | 0 | 1 |
|-----------|---|---|
| → q0 | {q0} | {q0, q1} |
| * q1 | {q2} | {q2} |
| * q2 | {q3} | {q3} |
| * q3 | {q4} | {q4} |
| * q4 | {q5} | {q5} |
| * q5 | ∅ | ∅ |

`∅` означает отсутствие перехода. ε-переходов нет. Недетерминизм возникает в `q0`: по символу `1` автомат может остаться в `q0` или перейти в `q1`.

![НКА, вариант 10](images/NFA.png)

**Идея.** Находясь в `q0`, автомат «угадывает», что прочитанная `1` окажется среди последних пяти позиций, и переходит в `q1`. Состояние `qk` (`k = 1…5`) означает, что после угаданной единицы прочитано ещё `k − 1` символов.

**Обоснование корректности.** Если `wᵢ = 1` и `i ≥ n − 4`, существует путь, который читает `w₁…wᵢ₋₁` по петле в `q0`, читает `wᵢ` переходом в `q1` и оставшиеся `n − i ≤ 4` символов проходит по цепочке `q1 → … → q(n − i + 1)`. Этот путь заканчивается в допускающем состоянии. Обратно, любой допускающий путь хотя бы раз уходит из `q0` в `q1`, а это возможно только по символу `1`. Путь не может выйти за `q5`, значит после этой единицы прочитано не более четырёх символов, то есть она стоит на одной из последних пяти позиций. Следовательно, НКА распознаёт в точности `L₂`.

Модель: [Variant10_NFA.jff](Variant10_NFA.jff).

## 3. Пошаговое распознавание тестовых цепочек

Окончательный ответ определяется после полного чтения цепочки. Ниже приведены последовательности состояний, выданные программой `Variant10.java`. Те же последовательности показывает JFLAP в режиме **Input → Step by State**.

### 3.1. ДКА — принятие цепочки 00100

Последовательность состояний ДКА: `q0 → q1 → q3 → q5 → q4 → q3`. После двух символов запомнена первая пара `00` (группа `q3…q5`). Далее окончание меняется так: `1` → `10` → `00`. Цепочка заканчивается в допускающем `q3`, так как окончание `00` совпадает с первой парой. Результат — **Accept**.

### 3.2. ДКА — отклонение цепочки 01010

Последовательность состояний ДКА: `q0 → q1 → q6 → q7 → q6 → q7`. Первая пара — `01`. Автомат дважды проходит через допускающее `q6`, но цепочка заканчивается на `10`, и конечное состояние `q7` не допускающее. Результат — **Reject**. Посещение допускающего состояния на промежуточном шаге не означает принятия всей цепочки.

### 3.3. НКА — принятие цепочки 0010000

| Прочитанный префикс | Активные состояния |
|---------------------|--------------------|
| ε | {q0} |
| 0 | {q0} |
| 00 | {q0} |
| 001 | {q0, q1} |
| 0010 | {q0, q2} |
| 00100 | {q0, q3} |
| 001000 | {q0, q4} |
| 0010000 | {q0, q5} |

Единица стоит на позиции 3 из 7, то есть на пятой позиции с конца. Ветвь, угадавшая её, доходит ровно до `q5`. Результат — **Accept**.

### 3.4. НКА — отклонение цепочки 1000000

| Прочитанный префикс | Активные состояния |
|---------------------|--------------------|
| ε | {q0} |
| 1 | {q0, q1} |
| 10 | {q0, q2} |
| 100 | {q0, q3} |
| 1000 | {q0, q4} |
| 10000 | {q0, q5} |
| 100000 | {q0} |
| 1000000 | {q0} |

Ветвь, угадавшая единицу на первой позиции, доходит до `q5` и на шестом символе обрывается: перехода из `q5` нет. Других единиц в цепочке нет, остаётся только недопускающее `q0`. Результат — **Reject**.

### 3.5. Сводные результаты проверки

ДКА и НКА распознают разные языки, поэтому их ответы на одну цепочку могут различаться.

|---------|-----|-----|
| ε | Reject | Reject |
| 0 | Reject | Reject |
| 1 | Reject | Accept |
| 00 | Accept | Reject |
| 01 | Accept | Accept |
| 10 | Accept | Accept |
| 000 | Accept | Reject |
| 001 | Reject | Accept |
| 010 | Reject | Accept |
| 111 | Accept | Accept |
| 0110 | Reject | Accept |
| 00100 | Accept | Accept |

Для всех 8191 цепочек над `{0, 1}` длиной от 0 до 12 результаты Java-реализации совпали с независимой проверкой условий языков и с симулятором JFLAP 7.1, загружающим соответствующие JFF-файлы. Этот конечный перебор дополняет доказательства корректности из раздела 2.

Чтобы повторить пошаговую проверку в JFLAP, откройте нужный JFF-файл через **File → Open**, выберите **Input → Step by State**, введите цепочку и нажимайте **Step**. Для проверки набора цепочек используется **Input → Multiple Run**.

## 4. Программная реализация

Файл: [Variant10.java](Variant10.java).

- `DFA[состояние][символ]` — таблица переходов ДКА (15 × 2), `DFA_FINAL` — допускающие состояния.
- `NFA[откуда][символ][куда]` — булева таблица переходов НКА (6 × 2 × 6), `NFA_FINAL` — допускающие состояния.
- `stepDfa` берёт следующее состояние из таблицы. `stepNfa` строит следующее множество активных состояний как объединение переходов из всех текущих.
- Ввод читается посимвольно через `System.in.read()`. Методы обработки строк (`String`, `Scanner`, `substring`, `indexOf` и т. п.) не используются.
- Символ вне алфавита `{0, 1}` переводит оба автомата в пустое состояние: цепочка отклоняется, как и в JFLAP.

Запуск:

```bash
javac Variant10.java
java Variant10
```

Каждая строка ввода — отдельная цепочка, пустая строка — ε, конец ввода (`Ctrl+D`) — выход. Для каждой цепочки программа печатает шаги (`Step`, `Read`, состояние ДКА, множество состояний НКА) и итог `Accept`/`Reject` для каждого автомата.

## 5. Возможность построения конечных автоматов

Для обеих частей варианта 10 конечные автоматы построены: ДКА содержит 15 состояний (минимальный), НКА — 6. Их корректность обоснована в разделе 2. Доказательство невозможности построения для этих языков не требуется.
