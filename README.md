## 3. Детерминированный конечный автомат

### 3.1. Анализ языка

Пара на левом краю - первые два символа, пара на правом краю - последние два:

`L₁ = {w ∈ {0, 1}* | |w| ≥ 2, w₁w₂ = wₙ₋₁wₙ}`, где `n = |w|`.

У цепочек длиной 0 и 1 нет пары символов на краю, поэтому они в язык не входят. При `n = 2` обе пары совпадают с самой цепочкой, поэтому любая цепочка длины 2 допускается. При `n = 3` пары перекрываются (`w₁w₂` и `w₂w₃`) и совпадают только у `000` и `111`.

Примеры: `00100`, `11011`, `01` принадлежат языку; `0`, `010`, `01010` не принадлежат.

### 3.2. Построение ДКА

Множество состояний: `Q = {q0, …, q14}`. Алфавит: `Σ = {0, 1}`. Начальное состояние - `q0`, множество допускающих состояний - `F = {q3, q6, q9, q12}`.

Автомат запоминает первую пару символов (она больше не меняется) и следит за окончанием прочитанной части. Состояния `q0`, `q1`, `q2` собирают первую пару. После второго символа автомат попадает в одну из четырёх групп по три состояния - по группе на каждую возможную первую пару - и больше из неё не выходит. Внутри группы три состояния соответствуют тому, сколько символов не хватает, чтобы окончание совпало с первой парой: 0, 1 или 2.

Таблица переходов (начальное состояние отмечено `→`, допускающие - `*`):

| Состояние | 0 | 1 | Первая пара | Окончание прочитанной части |
| --- | --- | --- | --- | --- |
| → q0 | q1 | q2 | - | ничего не прочитано |
| q1 | q3 | q6 | - | прочитан один символ `0` |
| q2 | q9 | q12 | - | прочитан один символ `1` |
| * q3 | q3 | q5 | 00 | `00` |
| q4 | q3 | q5 | 00 | `10` |
| q5 | q4 | q5 | 00 | `1` |
| * q6 | q7 | q8 | 01 | `01` |
| q7 | q7 | q6 | 01 | `0` |
| q8 | q7 | q8 | 01 | `11` |
| * q9 | q11 | q10 | 10 | `10` |
| q10 | q9 | q10 | 10 | `1` |
| q11 | q11 | q10 | 10 | `00` |
| * q12 | q14 | q12 | 11 | `11` |
| q13 | q14 | q12 | 11 | `01` |
| q14 | q14 | q13 | 11 | `0` |

**Обоснование корректности.** Первые два символа переводят автомат из `q0` через `q1` или `q2` в допускающее состояние той группы, которая соответствует первой паре. Это верно, потому что при `n = 2` цепочка всегда принадлежит языку. Дальше автомат остаётся в своей группе, то есть первая пара запоминается навсегда. Внутри группы состояние соответствует окончанию прочитанной части, записанному в таблице. Это проверяется по каждому переходу: например, в группе `00` из любого состояния по `1` окончание становится «`1`» (`q5`), из `q5` по `0` - «`10`» (`q4`), а из `q3` или `q4` по `0` - «`00`» (`q3`). Допускающее состояние каждой группы - единственное, в котором окончание совпадает с первой парой. Следовательно, автомат принимает цепочку ровно тогда, когда `w₁w₂ = wₙ₋₁wₙ`.

**Минимальность.** Состояния из разных групп различимы: они по-разному реагируют на продолжения. Внутри группы различимы допускающее состояние, состояние, из которого допускающее достигается одним символом, и состояние, из которого для этого нужно два символа. Алгоритм минимизации (Мура) не объединяет ни одной пары из 15 состояний, поэтому автомат минимален.

### 3.4. Программная реализация ДКА

ДКА задан в программе таблицей переходов `DFA[состояние][символ]` размером 15 × 2 и массивом допускающих состояний `DFA_FINAL`. Столбец 0 соответствует символу `0`, столбец 1 - символу `1`:

```java
static final int[][] DFA = {
    {1, 2},    // q0
    {3, 6},    // q1  - прочитано "0"
    {9, 12},   // q2  - прочитано "1"
    {3, 5},    // q3  - первая пара 00, окончание 00
    ...
    {14, 13},  // q14 - первая пара 11, окончание на 0
};
static final boolean[] DFA_FINAL = {
    false, false, false, true, false, false, true, false,
    false, true, false, false, true, false, false
};
```

Процедуры работы с таблицей:

- `symbolIndex(code)` - переводит код символа в номер столбца таблицы: `'0'` → 0, `'1'` → 1, другой символ → -1;
- `stepDfa(state, symbol)` - один такт: следующее состояние берётся из ячейки `DFA[state][symbol]`; символ вне алфавита даёт -1 (переход отсутствует);
- `acceptDfa(state)` - проверяет по `DFA_FINAL`, является ли состояние допускающим.

Цепочка читается посимвольно через `System.in.read()`, функции обработки строк не используются. После каждого символа программа печатает номер шага, прочитанный символ и текущее состояние, в конце - `Accept` или `Reject`.

## 4. Недетерминированный конечный автомат

### 4.1. Анализ языка

`L₂ = {w ∈ {0, 1}* | ∃ i: max(1, n − 4) ≤ i ≤ n, wᵢ = 1}`, где `n = |w|`.

Если цепочка короче пяти символов, последними пятью позициями считается вся цепочка. Пустая цепочка не содержит единиц и не допускается.

Примеры: `1`, `00001`, `10000`, `010000` принадлежат языку; `00000`, `100000` не принадлежат (в `100000` единица стоит на шестой позиции с конца).

### 4.2. Построение НКА

Множество состояний: `Q = {q0, q1, q2, q3, q4, q5}`. Алфавит: `Σ = {0, 1}`. Начальное состояние - `q0`, множество допускающих состояний - `F = {q1, q2, q3, q4, q5}`.

Таблица переходов (в ячейках - множества состояний, `∅` - перехода нет):

| Состояние | 0 | 1 |
| --- | --- | --- |
| → q0 | {q0} | {q0, q1} |
| * q1 | {q2} | {q2} |
| * q2 | {q3} | {q3} |
| * q3 | {q4} | {q4} |
| * q4 | {q5} | {q5} |
| * q5 | ∅ | ∅ |

ε-переходов нет. Недетерминизм возникает в `q0`: по символу `1` автомат может остаться в `q0` или перейти в `q1`.

**Идея.** Находясь в `q0`, автомат «угадывает», что прочитанная `1` окажется среди последних пяти позиций, и переходит в `q1`. Состояние `qk` (`k = 1…5`) означает, что после угаданной единицы прочитано ещё `k − 1` символов. Из `q5` переходов нет: после угаданной единицы может быть не больше четырёх символов.

**Обоснование корректности.** Если `wᵢ = 1` и `i ≥ n − 4`, существует путь, который читает `w₁…wᵢ₋₁` по петле в `q0`, читает `wᵢ` переходом в `q1` и оставшиеся `n − i ≤ 4` символов проходит по цепочке `q1 → … → q(n − i + 1)`. Этот путь заканчивается в допускающем состоянии. Обратно, любой допускающий путь хотя бы раз уходит из `q0` в `q1`, а это возможно только по символу `1`. Путь не может выйти за `q5`, значит после этой единицы прочитано не более четырёх символов, то есть она стоит на одной из последних пяти позиций. Следовательно, НКА распознаёт в точности `L₂`.

### 4.4. Программная реализация НКА

НКА задан булевой таблицей переходов `NFA[откуда][символ][куда]` размером 6 × 2 × 6: значение `true` означает, что переход есть. Так в одной ячейке «состояние × символ» хранится множество следующих состояний. Допускающие состояния - массив `NFA_FINAL`:

```java
static final boolean[][][] NFA = new boolean[NFA_STATES][2][NFA_STATES];
static final boolean[] NFA_FINAL = {false, true, true, true, true, true};
static {
    NFA[0][0][0] = true;
    NFA[0][1][0] = true;
    NFA[0][1][1] = true;
    for (int from = 1; from < 5; from++) {
        NFA[from][0][from + 1] = true;
        NFA[from][1][from + 1] = true;
    }
}
```

Процедуры работы с таблицей:

- `nfaStart()` - начальное множество активных состояний `{q0}`;
- `stepNfa(current, symbol)` - один такт: новое множество активных состояний - объединение по таблице переходов из всех текущих состояний;
- `acceptNfa(states)` - цепочка допускается, если среди активных состояний есть допускающее.

Программа печатает множество активных состояний после каждого символа - это те же конфигурации, которые JFLAP показывает в режиме пошагового выполнения.

## 5. Возможность построения конечных автоматов

Для обеих частей варианта 10 конечные автоматы построены: ДКА содержит 15 состояний (минимальный), НКА - 6. Их корректность обоснована в разделах 3.2 и 4.2. Доказательство невозможности построения для этих языков не требуется.

## 6. Вывод

В работе построены ДКА и НКА для языков варианта 10 в системе JFLAP и выполнена их программная реализация на Java с табличным представлением автоматов. Пошаговое выполнение в JFLAP и вывод программы на одних и тех же цепочках дают одинаковые последовательности состояний и одинаковые результаты `Accept`/`Reject`.

## Запуск программы

```bash
javac Variant10.java
java Variant10
```

Каждая строка ввода - отдельная цепочка, пустая строка - ε, конец ввода (`Ctrl+D`) - выход. Для каждой цепочки программа печатает шаги (`Step`, `Read`, состояние ДКА, множество состояний НКА) и итог `Accept`/`Reject` для каждого автомата. Символ вне алфавита `{0, 1}` приводит к отклонению цепочки обоими автоматами, как и в JFLAP.

Чтобы повторить проверку в JFLAP, откройте нужный JFF-файл через **File → Open** и выберите **Input → Step by State** (пошагово) или **Input → Multiple Run** (набор цепочек).
